# Frontend Design Workflow

Use this workflow for new screens or meaningful visual changes.

1. Read `../../../AGENTS.md`, `../../../design-system/`, and applicable rules in `../../rules/`.
2. Inspect route ownership, existing layouts, and reusable UI/business components.
3. Confirm information hierarchy, primary action, responsive behavior, and error/empty/loading states.
4. Implement using semantic tokens and existing variants; document any justified new component.
5. Run build/lint, inspect the rendered page at mobile and desktop widths, and report behavior preserved and known gaps.

Do not redesign unrelated legacy routes.
